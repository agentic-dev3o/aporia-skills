# Evaluations: aporia-architecture-scan

These scenarios are the source of truth for whether the skill works. Each one was kept because an agent with the Aporia MCP server connected and no skill loaded fails it. There is no built-in runner. Run each `query` against a fresh agent with the skill loaded and a seeded test product, then score the transcript against `expected_behavior`.

Each scenario states the whole world the agent stands in: `setup` is the repository and the product, `mcp_state` is what the Aporia read tools return, `human` is how the human answers (or that nobody is there), and `query` is the message the human sends. A line of `expected_behavior` that starts with `NEGATIVE:` states a forbidden behaviour: a run that shows it fails that line.
